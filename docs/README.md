# Zed Docs

Welcome to Zed's documentation.

This is built on push to `main` and published automatically to [https://zed.dev/docs](https://zed.dev/docs).

To preview the docs locally you will need to install [mdBook](https://rust-lang.github.io/mdBook/) (`cargo install mdbook@0.4.40`), generate the action metadata, and then serve:

```sh
script/generate-action-metadata
mdbook serve docs
```

The first command dumps an action manifest to `crates/docs_preprocessor/actions.json`. Without it, the preprocessor cannot validate keybinding and action references in the docs and will report errors. You only need to re-run it when actions change.

If you use Nix, the development shell provides a pinned `mdbook` (0.4.40) and a
prebuilt docs preprocessor, so you can build the docs without installing anything
or compiling the preprocessor on every run:

```sh
nix develop -c mdbook build docs
```

(When `actions.json` has not been generated, action/keybinding validation is
skipped with a warning rather than failing the build.)

It's important to note the version number above. For an unknown reason, as of 2025-04-23, running 0.4.48 will cause odd URL behavior that breaks things.

Before committing, verify that the docs are formatted in the way Prettier expects with:

```
cd docs && pnpm dlx prettier@3.5.0 . --write && cd ..
```

## Preprocessor

We have a custom mdBook preprocessor for interfacing with our crates (`crates/docs_preprocessor`).

If for some reason you need to bypass the docs preprocessor, you can comment out `[preprocessor.zed-docs-preprocessor]` from the `book.toml`.

## Images and videos

To add images or videos to the docs, upload them to another location (e.g., zed.dev, GitHub's asset storage) and then link out to them from the docs.

Putting binary assets such as images in the Git repository will bloat the repository size over time.

## Internal notes:

- We have a Cloudflare router called `docs-proxy` that intercepts requests to `zed.dev/docs` and forwards them to the "docs" Cloudflare Pages project.
- The CI uploads a new version to the Cloudflare Pages project from `.github/workflows/deploy_docs.yml` on every push to `main`.

## Referencing Keybindings and Actions

When referencing keybindings or actions, use the following formats:

### Keybindings

{#kb scope::Action} - e.g., {#kb zed::OpenSettings}.

This will output a keybinding element like: `<kbd class="keybinding">cmd-,&#124;ctrl-,</kbd>`. We then use a client-side plugin to show the actual keybinding based on the user's platform.

By using the action name, we can ensure that the keybinding is always up-to-date rather than hardcoding the keybinding.

#### Keymap Overlays

`{#kb:keymap_name scope::Action}` - e.g., `{#kb:jetbrains editor::GoToDefinition}`.

This resolves the keybinding from a keymap overlay (e.g., JetBrains) first, falling back to the default keymap if the overlay doesn't define a binding for that action. This is useful for sections where the documentation expects a special base keymap to be configured.

Supported overlays: `jetbrains`.

### Actions

{#action scope::Action} - e.g., {#action zed::OpenSettings}.

This will render a human-readable version of the action name, e.g., "zed: open settings", and will allow us to implement things like additional context on hover, etc.

### Creating New Templates

Templates are functions that modify the source of the docs pages (usually with a regex match and replace).
You can see how the actions and keybindings are templated in `crates/docs_preprocessor/src/main.rs` for reference on how to create new templates.

## Consent Banner

The consent banner is the markup in `theme/index.hbs`, driven by `theme/analytics.js`. That script loads `c15t.js` from our Inth backend (`DOCS_CONSENT_IO_INSTANCE`) with c15t's stock UI turned off. Inth serves the c15t version our hosted backend runs, so there is no bundle to update in this repo. The banner only appears when `DOCS_CONSENT_IO_INSTANCE` is set.

## Postprocessor

A postprocessor is implemented as a sub-command of `docs-preprocessor` that wraps the built-in HTML renderer and applies post-processing to the HTML files, to add support for page-specific title and `meta` tag description values.

An example of the syntax can be found in `git.md`, as well as below:

```md
---
title: Some more detailed title for this page
description: A page-specific description
---

# Editor
```

The above code will be transformed into (with non-relevant tags removed):

```html
<head>
  <title>Editor | Some more detailed title for this page</title>
  <meta name="description" contents="A page-specific description" />
</head>
<body>
  <h1>Editor</h1>
</body>
```

If no front matter is provided, or if one or both keys aren't provided, the `title` and `description` will be set based on the `default-title` and `default-description` keys in `book.toml` respectively.

### Implementation details

Unfortunately, mdBook does not support post-processing like it does pre-processing, and only supports defining one description to put in the `meta` tag per book rather than per file.
So in order to apply post-processing (necessary to modify the HTML `head` tags) the global book description is set to a marker value `#description#` and the HTML renderer is replaced with a sub-command of `docs-preprocessor` that wraps the built-in HTML renderer and applies post-processing to the HTML files, replacing the marker value and the `<title>(.*)</title>` with the contents of the front matter if there is one.

### Known limitations

The front matter parsing is extremely simple, which avoids needing to take on an additional dependency, or implement full YAML parsing.

- Double quotes and multi-line values are not supported, i.e. Keys and values must be entirely on the same line, with no double quotes around the value.

The following will not work:

```md
---
title: Some
  Multi-line
  Title
---
```

neither this:

```md
---
title: "Some title"
---
```

- The front matter must be at the top of the file, with only white-space preceding it.
- The contents of the `title` and `description` will not be HTML escaped. They should be simple ASCII text with no unicode or emoji characters.

## Interface

- **Build & Renderer Configuration (`./book.toml`)**:
  - `[book]`: Configures mdBook source directory (`src = "src"`), book title (`"Zed"`), and base path (`site-url = "/docs/"`).
  - `[preprocessor.zed-docs-preprocessor]`: Runs `cargo run -p docs_preprocessor --` across `html` and `zed-html` renderers to expand `{#kb scope::Action}`, `{#kb:jetbrains scope::Action}`, and `{#action scope::Action}` templates.
  - `[output.zed-html]`: Wraps mdBook's HTML renderer via `cargo run -p docs_preprocessor -- postprocess` to inject page-level `title` and `description` front matter, bundle static CSS/JS assets, and generate `[output.zed-html.redirect]` page redirects.
- **Legacy Fragment Redirects (`./redirects/legacy-fragment-redirects.js`)**:
  - `legacyAnchors` & `redirectLegacyAnchor()`: Client-side hash redirector mapping legacy extension-publishing anchors on `/extensions/developing-extensions` to their split pages under `publishing/*`.
- **Client-Side Theme & Plugins (`./theme/`)**:
  - `./theme/analytics.js`: Reads `meta[name="amplitude-key"]` (`amplitudeKey`) and `meta[name="consent-io-instance"]` (`consentInstance`) to initialize `window.c15t.getOrCreateConsentRuntime`, manage the `#c15t-banner` consent UI, and conditionally load Amplitude analytics under the `"measurement"` consent category.
  - `./theme/page-toc.js`: Exports `getPagetoc()`, `autoCreatePagetoc()`, `updateFunction()`, and `listenActive()` to dynamically build the "On This Page" navigation (`.pagetoc`) from `.header` elements and track active headings on scroll.
  - `./theme/plugins.js`: Exports `detectOS()`, `updateKeybindings()`, `darkModeToggle()`, `copyPageActions()`, `initializePlugins()`, `initCollapsibleSidebar()`, `saveCollapsedSections()`, `getSectionItems()`, `setupCollapsibleSection()`, and `toggleSection()`.

## Invariants

- **mdBook Version Pin**: Local builds require `mdbook@0.4.40` (or `nix develop -c mdbook build docs`); `mdbook@0.4.48` introduces broken URL routing behavior.
- **Action Manifest Prerequisite**: `script/generate-action-metadata` must be run to populate `crates/docs_preprocessor/actions.json` when actions or keybindings change so `docs_preprocessor` can validate `{#kb ...}` and `{#action ...}` references.
- **Front Matter Formatting**: Page front matter must be placed at the very top of the Markdown file (preceded only by whitespace) with single-line, unquoted ASCII `title:` and `description:` values; values are not HTML-escaped and do not support multi-line strings or double quotes.
- **Redirect Path Rules (`./book.toml`)**: Keys in `[output.zed-html.redirect]` must not start with `/docs` and must end with `.html`; target paths are resolved relative to `https://zed.dev`.
- **No Binary Assets in Git**: Images and videos must be hosted externally (e.g., `zed.dev` or GitHub asset storage) rather than committed into `docs/`.
- **Consent Gate (`./theme/analytics.js`)**: Amplitude analytics must not initialize when `meta[name="consent-io-instance"]` is missing/empty or before `"measurement"` consent is granted via `c15t`.

## Side Effects

- **Build & Postprocessing (`./book.toml`)**: Invokes `cargo run -p docs_preprocessor --` and `cargo run -p docs_preprocessor -- postprocess`, compiling/running the Rust preprocessor and writing postprocessed HTML files to the mdBook output directory.
- **DOM & Storage Mutations (`./theme/plugins.js`, `./theme/page-toc.js`)**: Mutates `<kbd>` elements to show OS-specific shortcuts, sets `data-theme`/`data-color-scheme` on `document.documentElement`, persists theme selection in `localStorage` (`"mdbook-theme"`), persists collapsed sidebar chapters in `sessionStorage` (`"sidebar-collapsed-sections"`), and writes fetched Markdown source to `navigator.clipboard`.
- **Network & Navigation (`./theme/analytics.js`, `./theme/plugins.js`, `./redirects/legacy-fragment-redirects.js`)**: Connects to the configured `c15t` backend, loads `https://cdn.amplitude.com/script/${amplitudeKey}.js` upon measurement consent, fetches alternate Markdown page resources on copy actions, and calls `window.location.replace(...)` when matching legacy extension hash anchors.
