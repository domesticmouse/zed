# compliance

## Overview

`compliance` (`tooling/compliance`) is a library crate that audits Git commit histories against GitHub Pull Request review records and bot-signature rules to verify that every commit in a release range was properly reviewed or generated by an untampered automated workflow (`zed-zippy[bot]`). It backs the `cargo xtask compliance` command.

## Interface

- `[src/lib.rs:checks]`, `[src/lib.rs:git]`, `[src/lib.rs:github]`, `[src/lib.rs:report]`: Re-exported top-level modules.
- `[src/checks.rs:Reporter]`: Coordinates compliance verification over a `CommitList` using an `Rc<dyn GithubApiClient>` (`Reporter::new`, `Reporter::result_for_commit`, `Reporter::check_commit`, `Reporter::is_qualifying_approval`, `Reporter::generate_report`).
- `[src/checks.rs:ReviewSuccess]`, `[src/checks.rs:ReviewFailure]`, `[src/checks.rs:AutomatedChangeFailure]`: Typed outcomes for commit approval checks and automated bot commit validation.
- `[src/git.rs:GitCommand]`, `[src/git.rs:Subcommand]`, `[src/git.rs:NoOutput]`, `[src/git.rs:GetVersionTags]`, `[src/git.rs:InfoForCommit]`, `[src/git.rs:CommitsFromVersionToVersion]`: Executes local `git` CLI commands and parses stdout into typed commit and tag records (`VersionTag`, `VersionTagList`, `ReleaseChannel`, `CommitSha`, `CommitDetails`, `CommitList`, `Committer`, `AutomatedChangeKind`).
- `[src/github.rs:GithubApiClient]`: Async trait abstracting GitHub REST and GraphQL operations (`get_pull_request`, `get_pull_request_reviews`, `get_pull_request_comments`, `get_commit_metadata`, `get_commit_files`, `check_repo_write_permission`, `add_label_to_issue`) over model types (`Repository`, `GithubUser`, `GithubLogin`, `PullRequestData`, `ReviewState`, `AuthorAssociation`, `Approvable`, `PullRequestReview`, `PullRequestComment`, `CommitAuthor`, `CommitSignature`, `CommitFileChange`, `CommitMetadata`, `CommitMetadataBySha`, `graph_ql`).
- `[src/github.rs:OctocrabClient]` (`feature = "octo-client"`): GitHub App JWT-authenticated implementation of `GithubApiClient` backed by `octocrab`.
- `[src/github.rs:PR_REVIEW_LABEL]`: Constant `"PR state:needs review"` applied to unreviewed PRs.
- `[src/report.rs:Report]`, `[src/report.rs:ReportEntry]`, `[src/report.rs:ReportSummary]`, `[src/report.rs:ReportReviewSummary]`: Aggregates per-commit check outcomes and renders Markdown compliance tables via `Report::write_markdown`.

## Invariants

- `[src/checks.rs:Reporter::is_qualifying_approval]`: A PR review or approval comment (`@zed-zippy approve` or `@zed-industries/approved`) only qualifies if the reviewer login differs from the PR author login and the reviewer's `AuthorAssociation` has write access (`Owner`, `Member`, or `Collaborator`).
- `[src/checks.rs:Reporter::check_commit_co_authors]`: If a PR lacks qualifying reviews or comments, a commit passes only if at least one `Co-authored-by:` trailer resolves to a GitHub user with repository write permissions.
- `[src/checks.rs:Reporter::check_zippy_automated_change]`: Commits without a PR number pass only if authored by `zed-zippy[bot]`, carry a valid GitHub signature (`CommitSignature::is_valid()`, `is_valid == true`), have no co-authors, mention a responsible `@actor` in the title, and touch the exact expected files and line counts (`VersionBump`: 2 additions / 2 deletions across `Cargo.lock` and `crates/zed/Cargo.toml`; `ReleaseChannelUpdate`: 1 addition / 1 deletion in `crates/zed/RELEASE_CHANNEL`).

## Side Effects

- `[src/git.rs:GitCommand::run]`: Spawns local `git` subprocesses to read tags and commit logs.
- `[src/github.rs:OctocrabClient]`: Performs HTTPS requests against GitHub REST and GraphQL APIs and mutates issue labels via `add_label_to_issue`.
- `[src/report.rs:Report::write_markdown]`: Writes Markdown compliance report files to the local filesystem.
